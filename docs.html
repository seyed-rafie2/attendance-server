معرفی

سیستم حضور و غیاب هوشمند دانشگاهی که بر پایه‌ی SSO دانشگاه (OIDC)، API دانشگاه و QR پویا کار می‌کند. استاد جلسه می‌سازد و QR چرخان نمایش می‌دهد؛ دانشجو با اسکن و تأیید بیومتریک گوشی خود، حضورش ثبت می‌شود.

قابلیت‌های اصلی

قابلیتتوضیح
🔐 ورود یکپارچهلاگین با اکانت دانشگاهی از طریق OIDC + PKCE — بدون رمز جداگانه
👥 تشخیص خودکار نقشاستاد یا دانشجو بودن از API دانشگاه مشخص می‌شود، نه از URL
🔄 همگام‌سازی خودکاردروس، دانشجوها و اطلاعات افراد از API دانشگاه کش و sync می‌شوند
📱 QR پویاQR هر ۱۰ ثانیه عوض می‌شود و با HMAC-SHA256 امضا می‌شود — عکس‌گرفتن QR بی‌فایده است
🖐️ بیومتریک واقعیتأیید هویت با WebAuthn (اثر انگشت/FaceID/PIN خودِ گوشی) — verify سمت سرور

جریان‌های کاربری

🧑‍🏫 جریان استاد
  1. صفحه اصلی → «ورود»
  2. SSO دانشگاه → لاگین با اکانت دانشگاهی
  3. برگشت به callback → سرور: GET /teachers/{sub} (نقش = teacher) سپس GET /teachers/{id}/courses (ذخیره دروس در DB)
  4. ریدایرکت به /teacher
  5. انتخاب درس → «شروع حضور و غیاب» → GET /courses/{id}/students + ساخت session
  6. نمایش QR پویا (هر ۱۰ ثانیه عوض می‌شود) + لیست زنده
  7. «پایان کلاس» → جلسه بسته، گزارش نهایی
🎓 دانشجو — بار اول
  1. ورود با SSO → تشخیص نقش student
  2. پنل /student → کارت «احراز هویت دستگاه»
  3. «ثبت این دستگاه» → اثر انگشت/PIN گوشی — کلید عمومی در سرور ذخیره می‌شود (فقط یک بار)
  4. ✅ دستگاه تأیید شد → دوربین روشن
🎓 دانشجو — دفعات بعد
  1. ورود با SSO
  2. «تأیید با بیومتریک» → پنجره‌ی ۱۲۰ ثانیه باز می‌شود
  3. اسکن QR استاد → ثبت خودکار حضور
  4. در پنل استاد، اسمش لحظه‌ای ظاهر می‌شود
📱
گوشی عوض شد؟ دکمه‌ی «+ ثبت دستگاه جدید» (تا سقف MAX_CREDENTIALS). دستگاه قبلی خودکار حذف نمی‌شود؛ در صورت نیاز ادمین باید رکورد مربوطه را از جدول webauthn_credentials پاک کند.

مدل امنیتی

لایه‌های احراز هویت

لایهمکانیزم
هویتOIDC + Authorization Code + PKCE + state + nonce
نقشتشخیص از API دانشگاه — دست‌کاری URL بی‌اثر است. 404 (پیدا نشد) از خطای عمومی API (سرویس down) تفکیک می‌شود تا در قطعی API، هیچ‌کس اشتباهی رد یا بلاک نشود
نشستکوکی httpOnly + sameSite=lax + secure در production + session.regenerate بعد از لاگین
QRامضای HMAC-SHA256 با secret اختصاصی هر جلسه + nonce + انقضا + چک timingSafeEqual + type-check سخت‌گیرانه ورودی
بیومتریکWebAuthn با userVerification: required — challenge از سرور، verify امضا و counter سمت سرور، پنجره‌ی زمانی ۱۲۰ ثانیه
دستگاهاتصال credential_id به دانشجو + چک اینکه یک credential برای دو نفر حضور ثبت نکرده

جریان تقلبی‌های رایج و جلوی آن‌ها

تلاش برای تقلبنتیجه
عکس گرفتن از QR و ارسال برای دوست❌ QR بعد از ۱۰ ثانیه منقضی می‌شود
ارسال biometric: {ok:true} جعلی با curl❌ بیومتریک دیگر ادعای کلاینت نیست؛ assertion وب‌آتنِ verify‌شده سمت سرور لازم است
ارسال device_id کپی‌شده❌ بر اساس credential_id (کلید داخل secure enclave) چک می‌شود
ساخت QR جعلی❌ بدون secret جلسه امضای معتبر ممکن نیست
ورود به /teacher با URL❌ نقش فقط از API دانشگاه؛ مسیر پنل‌ها هم پشت auth است

نکات استقرار

  • HTTPS اجباری است (Railway خودکار).
  • SESSION_SECRET ضعیف/ناموجود در production → سرور بالا نمی‌آید.
  • تعداد replica باید ۱ باشد (نشست در حافظه + SQLite).
  • پاسخ‌های QR کش نمی‌شوند (no-store).

ساختار دیتابیس

SQLite — فایل در DB_FILE — حالت WAL فعال.

جدولستون‌های کلیدیتوضیح
teachersid (PK), name, email, last_syncکش اطلاعات استاد
studentsid (PK), name, email, last_syncکش اطلاعات دانشجو
coursesid (PK), teacher_id, term, student_count, last_syncکش دروس
enrollmentsPK(course_id, student_id)ثبت‌نام — فقط از API دانشگاه پر می‌شود
sessionsid (PK), course_id, teacher_id, secret, statusجلسات حضور و غیاب
attendancePK(session_id, student_id), credential_id, scanned_at, qr_expرکوردهای حضور
webauthn_credentialscredential_id (PK), student_id, public_key, counterکلیدهای عمومی دستگاه‌ها

ایندکس‌ها: attendance(credential_id) · sessions(status) · courses(teacher_id) · enrollments(student_id)

مهاجرت: دیتابیس‌های نسخه‌ی قبل (بدون credential_id) به‌صورت خودکار با ALTER TABLE ارتقا می‌یابند.

کوئری‌های کاربردی ادمین

sql
-- گزارش حضور کل یک درس در همه جلسات
SELECT s.name, COUNT(a.session_id) AS حضور
FROM attendance a JOIN students s ON s.id=a.student_id
JOIN sessions se ON se.id=a.session_id
WHERE se.course_id='c101' GROUP BY s.id ORDER BY حضور DESC;

-- حذف دستگاه گم‌شده‌ی یک دانشجو
DELETE FROM webauthn_credentials WHERE student_id='s40211' AND credential_id='...';

  return asList(await apiFetch(`/lessons/${encodeURIComponent(id)}?active=true`), 'data').map(normCourse);
}
